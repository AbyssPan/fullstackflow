# 代码检索规范（查找代码时按需读取）

本文件供编排过程中定位代码时按需读取。

1. 给出文件路径、组件或类名时，使用 `kb-query.cjs` 精确定位；业务概念先检索知识库总览。
2. 读取命中源码和相关文档章节。同一源码版本已有的定位与影响面证据直接复用。
3. 共享组件、Store、公共服务/接口、公共工具变更，以及涉及上游入口的 Bug，必须用源码搜索和按需 LSP 查引用确认调用方、间接入口与回归项；局部改动按实际范围查证。
4. 证据记录仓库/文件/符号、提交号及相关工作区 diff 或文件摘要、查证位置、调用方、回归项和未确认范围，写进已有任务描述/交付说明。复用前确认相关源码未变，不能只比较 HEAD。
5. 审查检查调用方证据及其回归覆盖，不以工具名称或调用次数记 debt。动态注册、别名、路由等未确认的依赖如实交接，不猜测。

不得猜测文件路径和调用关系。当前实现事实冲突以源码为准；编码规范以知识库为准，疑似过期内容记录证据交 Phase 5 提交前确认更新或延期。

## 查证深度与失效条件

先找变更符号的定义与直接调用，再按接口、路由、注册表、事件订阅、Store 和序列化边界追踪到实际入口；动态关系需要查配置或运行证据，不能把搜索无结果等同于无人使用。
局部私有实现通常查直接调用即可；公共接口、共享状态、鉴权和持久化语义变化要继续确认跨域消费者。只把确需修改的路径放进 files，受影响但不需改动的路径列为回归项。

证据最小记录：对象（仓库/文件/符号）、版本（提交及相关工作区摘要）、依据（调用位置或运行观测）、结论（已确认消费者）、回归项、未确认范围。按角色写进现有 requirement-analysis、task description、development-notes 或测试报告。

相关代码、注册配置、依赖版本或接口契约变化后复核受影响部分；仅阶段切换不使证据失效。文档与源码矛盾先标明事实和规范的区别，不用历史摘要覆盖当前行为。
