# 浏览器与组件验证

> 来源：frontend-workflow v1.4.0 / `references/testing.md`（第五、六、七章），已裁剪适配 fsflow：不引入 Python 执行器与外部进程编排脚本，改为平台中立的项目脚本 + 进程树回收 + 端口校验表述。

## 环境就绪

确认测试 URL、目标端、启动命令、登录账号与后端依赖。优先复用已启动环境，核对地址确实对应本次代码版本。

需要启动时使用项目现有脚本，记录本次进程；以健康接口或页面关键元素确认就绪，**端口占用不代表服务可用**。

启动前必须确认目标端口空闲。已被占用时禁止直接再启一个（新进程绑定失败，测试实际连到旧进程 → 假绿）：先判断是否本任务残留，是则回收，否则改用空闲端口并记录冲突。

认证使用项目测试账号与夹具；账号缺失则交接所需条件。测试环境不可用时可运行独立单元/组件验证，但不能把结果扩大为端到端通过。

## 进程生命周期

只对**本次启动**的进程负责，不动用户已有服务：

1. 启动前记录：命令、端口、工作目录；
2. 启动后确认：端口监听 + 页面或健康接口可用；
3. 结束时回收：按进程树结束（Windows 下仅结束 shell 会残留 `node` 子进程占住端口）；
4. 回收后校验：端口已释放，不能只凭 kill 返回码；
5. 用例结束（成功/失败/异常/中断）均须回收，不"留着下次用"。

失败处理：端口仍被占用时不得标记测试完成，须报告端口、PID、命令并请求人工介入。来源不明或代码版本不确定的监听端口不得直接用于验证。

## 从观测到断言

动态应用先等页面稳定再探查，不等就查 DOM 是最高频错误：

1. 导航后确认页面稳定（关键接口返回、目标区域渲染完成）；
2. 侦察：整页截图 + 页面结构 + 关键 locator 探测；
3. 从渲染结果确定定位方式，优先 role / label / 可见文本 / 项目 test-id；
4. 再执行动作与断言。

使用条件等待：元素可操作、指定响应到达、业务状态出现。不要依赖固定 `sleep`，也不要强制等待全部网络静默（长轮询应用可能永不满足）。

操作后断言用户可见结果，以及适用的请求参数/响应；**不能只断言按钮存在或页面不报错**。

组件测试等待异步更新完成，Mock 网络/时钟边界，不 Mock 被测私有实现；避免用巨大快照代替业务断言。

## 用例与脚本映射

- 一条用例对应一个脚本或脚本内一个具名步骤，编号与用例文档一一对应（`TC-01` ↔ `tc-01-<slug>`）。
- 环境地址从参数或环境变量读取，不硬编码。
- 失败时输出：截图 + console/pageerror + 请求失败 + 失败断言上下文。

## 按变更选场景

- 表单：校验、提交、防重复、成功反馈、失败保留输入；确认持久化由真实操作触发。
- 搜索/分页：快速切换、旧响应迟到、空结果、越界；核对显示数据与最新参数一致。
- 弹窗/路由：键盘、焦点返回、关闭/卸载时异步与监听器清理，检查返回入口。
- 响应式：需求指定视口、长文本与图片失败，检查可操作性和溢出。
- 权限：不同角色或账号切换后，迟到响应与新视图状态不得互相污染。
- 接口不可用时可验证 Mock 驱动的前端状态，明确标注；涉及真实保存/鉴权/联调的 AC 仍为 unverifiable。

## 失败与视觉证据

记录动作序列、预期/实际、截图、相关 console 与请求失败；先区分断言失败、超时、环境故障，再决定是否重试。

视觉检查固定视口、字体、数据、时区和动效状态，按项目阈值比较并人工检查业务含义。不能用任意统一像素百分比保证所有页面质量。

基线更新必须说明对应的预期视觉变化，不能为消除差异直接重录。视觉吻合不能代替交互验收。

只重试已定位的暂态环境失败并限定次数，保留首个失败记录；不能重跑到绿后隐藏不稳定结果。

## 回归成立条件

一条"回归用例"要成立，必须完成 Red-Green：

1. 用例在缺陷存在时可稳定失败（并记录失败签名）；
2. 修复后通过；
3. 还原修复（或临时回退到修复前）必须再次失败；
4. 恢复代码后再次通过。

只跑一次通过不算回归成立。无法完成第 3 步时，在证据中说明原因并降级为"验证用例"，不得称为回归用例。

跳过的用例在用例文档标注 ⏭ 与原因，静默跳过视为未验证。
