# backend-tech-spec — 后端规范解析与执行

本 skill 为全栈开发工程师提供后端编码基线。它不是覆盖所有项目的固定模板；先确定当前任务实际适用的规范，再编码或审查。

## 规范优先级

按以下顺序解决冲突，高优先级覆盖低优先级：

1. 用户本次明确要求、验收标准和已确认的技术决策。
2. 当前项目知识库中与本模块、语言或框架匹配的编码规范，以及知识库中的人工批注。
3. 仓库级指令、格式化/静态检查配置、架构决策记录和项目文档。
4. `harness-conductor` 的内置 OpenCodeReview 抽取规则：
   [Java](../harness-conductor/references/review-rules/java.md)、
   [Mapper/DAO XML](../harness-conductor/references/review-rules/mapper_dao_xml.md) 和
   [其他后端文件](../harness-conductor/references/review-rules/default.md)。
5. 相邻既有代码形成的稳定约定与当前依赖实际支持的写法。
6. 本 skill 的默认规范。

“知识库优先”只适用于其覆盖范围明确且内容可执行的规则。知识库缺失、未命中当前模块或没有涉及某项约定，不等于冲突；此时继续向下取规则。知识库明显过期并与可运行源码或依赖版本冲突时，不要静默套用任一方：保留兼容实现，并在交付说明中列出冲突证据和待确认项。

安全、数据正确性和用户明确要求不因低优先级风格约定而降级。

## 编码前解析

1. 通过 `kb-query` 查询当前业务域的 `overview.md`、`architecture.md`、`api.md`、`pitfalls.md` 和 `custom/` 中的规范。知识库若未初始化，直接使用仓库事实与下级规则；不在本 skill 中再次询问或初始化。
2. 读取任务涉及模块的构建文件、框架配置、格式化/检查配置及 2–3 个相邻实现，确认语言、框架、版本、目录、API、持久化、时间类型、注入方式和测试方式。
3. 按变更文件类型读取上述内置审查规则：Java 读 `java.md`，Mapper/DAO XML 读 `mapper_dao_xml.md`，其他后端文件读 `default.md`。这些规则高于本 skill 的默认规范；规则未覆盖的事项才由本 skill 补位。
4. 形成一份简短的“本次适用规范”：
   - `项目规则`：来自知识库或仓库的明确要求；
   - `沿用约定`：从相邻代码确认的稳定模式；
   - `默认补位`：项目未规定、由本 skill 提供的规则；
   - `冲突/未知`：需要兼容处理或在交付中说明的事项。
5. 仅加载与实际技术栈匹配的参考。Java + Spring Boot + MyBatis/MyBatis-Plus 项目或新项目采用该栈时，读取 [references/java-spring-boot.md](references/java-spring-boot.md)。其他后端技术栈只执行本文件中的通用基线，不强行套用 Java 约定。

不要为了“统一”而批量改写任务范围外的旧代码、目录或 API。

## 通用后端基线

以下规则仅在项目规范和内置审查规则都没有覆盖时采用：

- 保持职责边界清楚：传输、业务、持久化和外部集成代码可追踪，Controller/handler 不承载核心业务。
- 接口请求和响应使用明确类型与稳定契约；业务数据不使用无结构的 `Map<String, Object>`。校验、错误语义、鉴权、分页/排序和幂等要求在适用时写清楚。
- 数据库查询参数化，禁止拼接不可信 SQL；避免 `SELECT *`、N+1、无界列表和循环单查；索引与分页结合实际查询验证。
- 多步写操作按业务原子性设置事务；检查事务代理失效、异常吞噬、并发更新和重复提交。
- 异步只用于确认可异步且允许最终一致的工作；使用项目托管、可观测且有界的执行器，明确拒绝策略、上下文传播、失败处理和停机行为。不得为追求“异步化”改变业务语义。
- 配置、外部地址、密钥、开关和超时进入项目配置体系；敏感值不得写入源码、日志或示例。
- 日志包含必要业务上下文但不泄露敏感数据；异常保留原因和堆栈，不使用 `System.out` 或等价临时输出。
- 新增代码配套最低必要测试，并运行项目已有的格式化、静态检查、测试或编译命令。未经授权不要扩大成全库重构。

## 条件规则

下列约定只有在知识库、仓库配置、相邻代码或用户选择已确认时才可设为强制，不得仅因附件模板出现就推断所有项目都采用：

- 固定 `/v1/...` 路径、全部使用 POST、禁止路径参数或统一 `operateType` 接口；
- `zbId` / `userId` 的固定名称与基本类型；
- MyBatis-Plus、Nacos、Feign、Hutool、Swagger 版本及其特定注解；
- 字段注入或构造器注入、Service 接口/实现拆分、是否继承框架基类；
- `java.util.Date`、固定 `GMT+8`、数据库字段名和 PO/DTO/VO 包路径；
- 每个字段显式 `@TableField`、逻辑删除字段、统一分页基类等工程模板；
- 文件数量最少、相似写操作合并等组织偏好。

若是全新 Java/Spring Boot 项目且用户没有指定这些选择，使用参考文档中的现代默认值，而不是将上列团队特有约定自动设为硬规则。

## 交付检查

交付说明中简要写明：

- 本次采用了哪一层规范，知识库是否命中；
- 哪些规则由本 skill 补位；
- 是否存在知识库、源码、依赖或接口契约冲突；
- 已执行的测试/编译，以及未执行项和原因。
