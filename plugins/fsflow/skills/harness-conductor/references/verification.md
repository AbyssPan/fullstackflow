# 验证、授权与交付约定

## 证据与结论

每项完成声明必须对应实际证据：代码已写入看 diff；lint/类型/构建各看对应命令；Bug 修复看原症状复测；需求满足逐项对照 AC。
记录版本（HEAD 加相关工作区变更）、范围、环境、命令/操作、退出码或断言结果、未覆盖项。同版本同范围且环境未变化的证据可以复用；相关代码、配置、依赖或环境变化后重新验证受影响部分，不按消息轮次机械重跑。
子 Agent 自述、文件存在、Schema 合法只能证明对应事实，不能独立证明业务正确。主控核对产物与证据，不凭“已完成”推进。

| 实际情况 | 可报告结论 |
|---|---|
| 代码修改完成，未运行 | 已实现，运行行为待验证 |
| 部分检查通过 | 列明已通过范围和剩余缺口 |
| 运行结果不符合预期 | 验证失败，附预期/实际和证据 |
| 环境或权限阻塞 | 无法验证，说明缺少条件与可执行下一步 |

只读审查需检查实际命令定义：npm run lint 可能包含 --fix，tsc 可能生成增量缓存；不要仅凭名称判断无写入。只执行与角色权限相符的检查。

## 授权与流程边界

沿用当前会话明确的范围和授权，日常定位、实现、自测不增加重复确认点。外部发布、消息发送、环境变更等按当前授权执行，缺失授权时展示具体对象与操作再询问。
独立功能测试遵守 verificationMode；本文件不覆盖用户跳过选择。技能不能手改 e2e-state/dev-pass 或自行推进阶段。
文档来源、常规实现细节可由仓库事实确定时先查证；只有影响产品行为、范围或无法从事实确定的决策才交用户裁决。
