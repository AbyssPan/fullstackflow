# 配置与数据变更复核

先确认文件用途与消费者，不能只按扩展名推断规则。默认检查以下与本次变更相关的事项：

- package/锁文件：声明与解析版本是否一致、运行时兼容、脚本真实副作用、是否引入不必要依赖；不能未查询就声称某版本存在已知漏洞。
- 构建/CI/环境配置：变量名称与读取方一致、环境分支和部署目标正确、所需变量是否实际注入、客户端构建是否包含敏感值。
- JSON/YAML/XML：语法与实际 Schema、键名变更的消费者、空值/字符串/布尔值语义、默认值和覆盖顺序。
- SQL/迁移：数据规模、锁表风险、默认值/null、唯一约束、索引与查询模式、旧数据迁移及应用发布顺序；没有 WHERE 不自动证明全表扫描有害。
- 接口/服务配置：超时、重试与幂等、事务边界、缓存失效、配置删改对调用方的影响。
- 删除/重命名：构建入口、导入、配置引用和运行时动态查找是否同步更新；不能因为只有删除行就跳过行为影响。

不执行迁移或部署来“验证”审查猜测。缺环境或统计数据时明确未确认范围，给出需补充的证据。
