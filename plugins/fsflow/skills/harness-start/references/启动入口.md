# 启动入口

> 仅在新建 Story、写 `story-input.json` 时读取。

## 1. 写入原始输入

```bash
HARNESS=${CLAUDE_PLUGIN_ROOT}/scripts/commands
STORY_DIR=${CLAUDE_PROJECT_DIR}/.codebuddy/plans/<storyId>
```

写 `${STORY_DIR}/story-input.json`。`storyId` / `title` / `createdAt` 由脚本回填；链接、参数和补充描述原样搬运。

```json
{
  "mode": "run",
  "verificationMode": "full",
  "sources": {
    "prototypeUrls": ["https://proto.example.com/xxx"],
    "figmaUrls": ["https://www.figma.com/design/AbC123/example?node-id=12-345"],
    "terminal": "H5",
    "text": "用户的补充描述"
  }
}
```

`mode` 取 `run` 或 `fixbugs`。`verificationMode` 可选：

- `full`（默认）：保留 Phase 4 独立功能测试。
- `review-only`：只在用户明确要求快速流程或跳过独立测试时写入；代码审查、lint/编译和项目 git hook 仍保留。

`sources` 按用户实际给出的内容选填：

| 字段 | 场景 | 作用 |
|---|---|---|
| `tapdUrl` `workspaceId` `storyIdInTapd` `owner` `statusFilter` | fixbugs | Phase 0 拉取和筛选缺陷 |
| `prototypeUrls` | run | 非空时要求原型分析 |
| `figmaUrls` | 两者 | run 自动开 Figma 门控；fixbugs 仅注入指引 |
| `terminal` | 两者 | H5 / PC / 小程序等终端上下文 |
| `docs` | 两者 | 需求文档路径 |
| `text` | 两者 | 剩余原始描述与约束 |

Schema 在 `scripts/schemas/story-input.schema.json`，未登记字段会使启动失败。

## 2. 启动

```bash
node $HARNESS/harness-workflow.js start <storyId> "<标题>" --input=${STORY_DIR}/story-input.json
```

`--input` 在写状态前校验输入，并一次算准模式、原型、Figma 和验证策略，无需再传 `--mode`
或执行 `--refresh-input`。校验失败不会留下半激活状态。

启动成功必须确认输出含 `e2eStateCreated: true` 和 `story-input.json: ✅ 已摄入`。
