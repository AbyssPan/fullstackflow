# 审查后修复

**适用**：只需要处理审查发现的几个问题，不重跑整个需求。

## 第一步：先审

```
/fsflow:only code-review "审查当前工作区未提交改动，只看 BLOCKER 和 WARNING"
```

## 第二步：只修这些

把问题清单贴进去，避免它顺手重构：

```
/fsflow:fixbugs "修复以下审查问题，只改这些，不要动其他文件：
1. src/views/order/list.vue:42 — 筛选变更后旧请求未取消，快速切换会显示上一次的结果
2. src/api/order.js:18 — 错误分支吞掉了 code，前端无法区分无权限与网络失败"
```

## 已在流程中时

如果审查是 Phase 3 产出的，直接说：

```
继续 <storyId>，修复审查发现的问题
```

流程会按 `code-review.json` 里的未关闭问题进入 fix-loop，不需要重新描述。

## 注意事项

- 一次只修一类问题。把「顺手重构 + 修 bug」混在一起，会让审查无法区分改动意图。
- 贴问题清单时保留文件与行号，位置越具体越不容易误改。
- 修复后要重新验证：说「修完了，跑一遍相关测试」比「应该没问题了」有效。
- 纯风格建议（SUGGESTION）默认不进修复范围，除非明确要求。
