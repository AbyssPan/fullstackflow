# 前端工程规则

> 来源：frontend-workflow v1.4.0 / `references/frontend-engineering-standards.md`（第一~七章），已裁剪适配 fsflow：移除业务文档接入编排与本地进程生命周期两章（前者与 story/OpenSpec 内嵌规则冲突，后者依赖外部脚本），补充既有项目实战条款。

本文件是**内置基线**。优先级链见 `SKILL.md`：用户要求与 AC → 项目知识库/仓库规范 → 本文件 → 相邻代码稳定约定 → 技能默认值。项目规范可以更严，不能降低安全与数据正确性要求。

## 一、类型与边界

- TS 项目沿用项目 strict 与 lint 配置，不自行放宽；外部未知数据（接口、storage、URL 参数、postMessage）先校验再收窄。
- 断言只表达**已有证据**：`as` 用于"已校验过的收窄"，不用于"希望它是这个类型"。
- 必要的兼容 `any` 限定在边界函数内，注释说明原因与收敛计划。
- JS 项目沿用 JSDoc 或既有校验方式，不为本次任务引入 TS。
- props、事件、接口、空值语义保持明确：区分缺省、`null`、空串、`0`、`false` 五种情况，不用 `if (!x)` 统一处理。
- 展示状态、请求状态、业务领域状态按现有模块边界分开，不混在一个大对象里。
- 只抽取实际复用或明显妨碍理解的逻辑，**不按函数/组件行数机械拆分**。

反例：用 `as unknown as T` 抹平接口差异；为"类型完美"给每个字段加一层映射，导致改一个字段要改四处。

## 二、请求与异步

1. 先查明项目请求层是否已解包 data、转换字段、处理鉴权与错误、分页与取消。**复用封装，不创建第二套拦截器**。
2. 覆盖 loading / success / empty / error 四态；保存类操作另检查 pending、重复提交、失败后的输入保留与重试入口。
3. 空态与错误态的视觉呈现按 `design.md` 三段分级判定：设计已画则还原，未画而项目已有模式则沿用，都没有才补最小可用形态。
4. 快速搜索、切换参数、翻页时，取消过期请求或用请求序号阻止旧响应覆盖新状态；**旧请求的 finally 也不能提前关闭新请求的 loading**。
5. 取消异常按实际请求库识别，**不一律按 AbortError 判断**（如 axios 的 `CanceledError`、自研封装的业务取消码）。
6. 卸载、切换账号、权限变化后，迟到的结果不能污染新视图或其他用户的缓存。
7. 请求取消不代表服务端写操作已撤销；写操作重试须遵守幂等契约。
8. 错误在能恢复或能反馈的边界处理；继续抛出时保留原因。不要求每层都套 try-catch，也不能吞错后伪装成功。

反例：`catch` 里只 `console.error` 却照常把 `loading = false`、列表置空，用户看到"暂无数据"而实际是请求失败。

## 三、状态与生命周期

状态存放按分级判断，不默认上 Store：

```
该状态被多个不相关组件共享？
├── 是 → Store / 全局缓存
└── 否 → 组件卸载后还需保留？
    ├── 是 → Store，或父组件 + 缓存机制
    └── 否 → 组件本地状态
```

- 派生值用 getter / computed / selector 计算，不维护第二份真源，也不用 watch 把 A 同步到 B。
- 区分服务器数据缓存与 UI 临时状态（展开、hover、草稿），失效与刷新策略按现有库实现。
- 监听器、订阅、定时器、观察器在实际生命周期结束时释放。弹窗打开即销毁、路由复用、缓存激活/停用三种情况都要考虑。
- Vue 2 按依赖支持处理响应式新增属性与数组更新，在 `beforeDestroy` 清理。
- Vue 3 用对应组合式生命周期，`onUnmounted` 覆盖所有副作用。
- React 遵守 Hooks 顺序与依赖规则，检查闭包旧值及 effect 清理。
- 小程序确认页面/组件卸载与隐藏的区别，控制 `setData` 体积和频率，不照搬 DOM API 或浏览器事件模型。

反例：把 `props` 复制到本地 data 再 watch 回写父组件，形成双向回写环；为省事用索引做列表 key 导致删除后状态错位。

## 四、安全

- 文本用框架默认转义；富文本使用项目认可的净化方案，不直接 `v-html` / `innerHTML` 渲染未净化内容。
- URL 按用途验证协议与目标，不把不可信地址直接用于导航或 HTML（禁 `javascript:` / 非预期 `data:`）。
- 前端变量与构建产物可被用户读取；放进 `.env` 不会使打包到客户端的密钥保密。
- 敏感操作依赖服务端鉴权，前端校验只用于反馈与减少无效请求。
- 日志与验证证据脱敏；认证信息不进入 URL、截图或提交文件。
- 隐藏按钮不等于鉴权；前端可见性只是体验层。

反例：把 token 拼进查询串（会进日志与浏览器历史）；用 `v-html` 渲染用户昵称"为了支持表情"。

## 五、性能

- 以测量或具体开销为依据判断，不为"可能更快"引入未采用的组件库或改变业务语义。
- 长列表按真实数据规模选择分页或虚拟化；数据量不确定时先确认上限再选方案。
- 图片设置合理尺寸并按首屏需求选择加载策略；不无差别 `@2x` 或全量预加载。
- `scroll` / `resize` / `input` 按实际频率节流并清理监听。
- 避免不必要的重渲染：稳定引用、合理拆分粒度、避免在渲染期创建新对象/函数作为子组件 props。
- 同时使用 `v-loading` 与滚动事件时，确认遮罩宿主与真实滚动容器，避免遮罩或 `overflow` 改变滚动目标；必要时分层承载，而非对所有布局机械套模板。

反例：给列表每项加 `memo` 但每次都传新对象字面量；为"优化"把整页塞进一个 `computed`，依赖一变全量重算。

## 六、注释与文档

- 文件/组件级：说明职责、输入输出、关键约束（谁调用、依赖什么全局状态）。
- 复杂逻辑写"为什么这么做"，不复述代码逐行翻译。
- 公共函数与请求封装用 JSDoc 标注参数、返回、异常与副作用。
- `TODO` / `FIXME` / `HACK` 必须带触发条件或责任人，不留下无法判定的长期标记。
- 注释与代码同步修改；过时注释比没有注释更危险。

反例：`// 设置 loading 为 true` 这类翻译式注释；改了逻辑但沿用旧注释描述。

## 七、不确定时的处理

**必须停下询问**：

- 接口契约（字段是否存在、是否必填、错误码语义）无法从源码或文档确认；
- 业务规则与状态流转（谁能操作、什么条件下可见）；
- 设计取舍会影响验收（同一交互有多种合理解法）；
- 权限边界（是前端隐藏还是服务端拦截）。

**严禁猜测**：字段含义、枚举取值、金额与精度口径、状态机转移条件。

**降级方式**：可用可验证的默认实现，但必须在交付说明里写 `⚠️ 待确认：<具体问题>`，并说明当前实现依据；不得把猜测写成既定事实。

提问前先自查可查证的事实（源码、类型定义、知识库、既有调用）；事实自查不消耗提问额度，决策类问题才交给用户。
