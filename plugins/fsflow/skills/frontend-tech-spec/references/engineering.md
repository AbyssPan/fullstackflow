# 前端工程规则

## 类型与边界

- TS 项目沿用 strict 和 lint 配置；外部未知数据先校验再收窄。断言只表达已有证据，不把接口猜测伪装成类型；必要的兼容 any 限定边界并解释原因。
- JS 项目沿用 JSDoc 或已有校验方式，不为本次任务引入 TS。Props、事件、接口和空值语义保持明确；区分缺省、null、空串、0、false。
- 展示、请求和业务状态按现有模块边界分开。只抽取实际复用或明显妨碍理解的逻辑，不按函数/组件行数机械拆分。

## 请求与异步状态

1. 查明项目请求层是否已解包 data、转换字段、处理鉴权/错误、分页和取消。复用封装，不创建第二套拦截器。
2. 覆盖 loading、success、empty、error；保存类操作另检查 pending、重复提交、失败后的输入保留与重试入口。错误应有用户可感知反馈，避免封装层和页面重复提示。
3. 快速搜索/切换参数时，取消过期请求或用请求序号阻止旧响应覆盖新状态；旧请求的 finally 也不能提前关闭新请求的 loading。取消异常按实际请求库识别，不一律按 AbortError 判断。
4. 卸载、切换账号和权限变化后，迟到的结果不能污染新视图或其他用户的缓存。请求取消不代表服务端写操作已撤销；写操作重试遵守幂等契约。
5. 异常在能恢复或反馈的边界处理，继续抛出时保留原因。不要求每层都套 try-catch，也不能吞错后伪装成功。

## 状态与生命周期

- 局部状态留在组件；跨组件共享或跨卸载保留才使用项目 Store/缓存。派生值由 getter/computed/selector 计算，避免同时维护多份真实来源。
- 区分服务器缓存与 UI 临时状态，失效/刷新策略按现有库实现，不强制为每类状态新建 Store。
- 监听器、订阅、定时器、观察器在实际生命周期结束时释放；弹窗打开时销毁、路由复用、缓存激活/停用都要考虑。
- Vue 2 按依赖支持处理响应式新增属性与数组更新、beforeDestroy 清理；Vue 3 用对应组合式生命周期。React 遵守 Hooks 顺序和依赖规则，检查闭包旧值及 effect 清理；性能优化以测量或具体开销为依据。
- 小程序确认页面/组件卸载与隐藏的区别，控制 setData 体积和频率，不能照搬 DOM API 或浏览器事件模型。

## 安全与性能

- 文本用框架默认转义；富文本使用项目认可的净化方案。URL 按用途验证协议和目标，不能将不可信地址直接用于导航或 HTML。
- 前端变量与构建产物可被用户读取；放进 .env 不会使打包到客户端的密钥保密。敏感操作仍依赖服务端鉴权，前端校验用于反馈与减少无效请求。
- 日志和验证证据脱敏；认证信息不进入 URL、截图或提交文件。
- 长列表按真实数据规模选择分页/虚拟化；图片设置合理尺寸并按首屏需求选择加载策略；scroll/resize 按实际频率节流并清理。不要为了优化引入未采用的组件库或改变业务语义。

## 样式与框架适配

- 静态样式优先 class 和项目样式体系；动态尺寸/位置可以使用受控样式变量，不将禁止内联写法绝对化。
- 深度选择器按当前 Vue 与预处理器支持选择；不要新增已不兼容的 /deep/ 写法。涉及选择器/预处理器时验证实际编译。
- 同时使用 v-loading 与滚动事件时，确认遮罩宿主与真实滚动容器，避免遮罩或 overflow 改变滚动目标；必要时分层承载，而非对所有布局机械套模板。
