# 前端复核与误报边界

> 来源：frontend-workflow v1.4.0 / `references/figma-design-constraint.md`（第二、八、十章）与 `frontend-engineering-standards.md`（第四、五章），已裁剪为审查可判定项。

前置：**项目明确规范优先于本手册**。报告前先确认项目是否已有等价约定；有则按项目约定判定，不把本手册当唯一标准。

## 通用

- **功能**：AC 所需入口、渲染、交互、持久化与错误反馈是否真实连接；检查缺省值与空值、请求参数、迟到响应、账号切换和生命周期清理。
- **组件集成**：查路由、父组件、注册表、自动导入配置、动态 import 和模板。只有证实需求要求的入口不可达时才报告；组件库导出、自动注册或间接引用不能因没有页面直接 import 而报错。
- **契约**：核对路径、方法、字段映射、序列化、分页与错误语义。额外响应字段未被消费本身不是问题；需求必须展示/处理的数据缺失，或前端读取不存在的字段才需查证影响并定级。
- **安全**：验证不可信内容进入 HTML/URL 的路径、已有净化防护与服务端授权边界；不能把纯文本插值误判成注入，也不能认为隐藏按钮等于鉴权。
- **交互与可访问性**：检查键盘、可访问名称、焦点、加载/失败/空态、目标视口；设计未画状态时仍检查项目既有交互规范。
- **性能**：结合数据规模、触发频率和测量判断重渲染、长列表、资源与监听开销。不因没有 memo/虚拟列表自动报告。
- **规范**：用实际框架/编译器/lint 配置判断写法；必要的类型边界、动态样式和合法注册机制不能被模板禁令误报。

## 设计还原

- **声明与实现是否一致**：任务声称"像素级还原"时，核对尺寸、间距、颜色、字号、行高、圆角、阴影是否与设计数据一致；差异要给出具体属性与两侧取值。未声明像素级还原的普通改动不按此条判定。
- **资源来源**：确认图片/图标来自设计交付或项目已有资源；用第三方图标库或占位图冒充完成还原属于 BLOCKER。项目本身统一使用图标库时，不判违规。
- **状态覆盖**：设计中已画的状态是否全部实现（hover / active / focus / disabled / loading / empty / error）；缺项要说明是哪种状态、在哪个交互路径上缺失。

## Token 与作用域

- **作用域陷阱**：`:root` 写进 `<style scoped>` 会被编译成 `:root[data-v-xxx]`，`<html>` 不匹配导致 Token 静默失效。这是可证实的缺陷，需给出文件与行号。
- **重复定义**：同一 Token 在本轮改动文件中重复声明，或组件内新声明了全局入口已有的同名 Token。判定前先排除项目既有的主题覆盖与局部变量机制——**不把所有同名变量判成重复缺陷**。

## 反例（不得据此报缺陷）

| 情形 | 为什么不报 |
|---|---|
| 用了组件库默认的 hover / disabled / focus 样式 | 属项目既有实现，设计未画不等于禁用 |
| 空态/失败态有图标与文案 | 设计未画但功能必需，按 `design.md` 三段分级第 2、3 种情形处理 |
| 组件内声明了局部变量且项目允许该机制 | 不是全局 Token 重复定义 |
| 未使用 memo / 虚拟列表 | 无规模证据时不构成性能缺陷 |
| 未直接 import 某组件 | 可能经自动注册、动态导入或注册表间接使用，需先查路由与父组件 |

## 报告要求

每个问题说明：具体触发条件、证据位置（文件与行号）、受影响 AC 或入口、修复方向。能通过上下文排除的候选问题不进入问题清单；纯风格偏好不升级为功能缺陷。
