# 多仓库任务

**适用**：前端与后端（或主仓与共享库）在不同仓库，一个需求要同时改。

## 可粘贴命令

在需求描述里点明仓库关系与本地路径，流程会据此生成 `repos.json` 并逐个确认：

```
/fsflow:run "退款功能同时改前端 app 仓库与后端 api 仓库，前端在 ../app，后端在 ../api"
```

主仓固定为当前工作目录，其余仓库按描述里的相对路径解析。

## 要说明的三件事

1. **哪个是主仓**：其余仓库按主仓的相对位置解析，主仓即当前工作目录。
2. **改动落在哪个仓**：每个仓改什么，不要只写「前后端都改」。
3. **依赖顺序**：后端接口先上还是前端先兼容，影响批次串行顺序。

## 示例

```
/fsflow:run "退款申请加审批流。
前端（主仓，当前目录）：订单详情页加审批状态与审批按钮，仅主管可见。
后端（../api）：新增 approve / reject 接口，审批记录落表。
先后端定接口，前端按接口联调；两个仓都要过审查与测试。"
```

## 注意事项

- 所有仓库必须是本地可读路径；远程地址不会被克隆。
- 每个仓独立审查、独立出证据；某一仓不可读时报告阻塞，不会伪造通过。
- 跨仓公共代码变更会要求确认调用方与回归项，这属于正常流程，不是卡住。
