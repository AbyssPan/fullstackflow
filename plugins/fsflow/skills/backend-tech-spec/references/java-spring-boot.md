# Java / Spring Boot 默认规范

仅在实际项目是 Java + Spring Boot，且更高优先级规范没有覆盖对应事项时使用。项目采用 MyBatis、MyBatis-Plus、Nacos、Feign 或 OpenAPI 时，只启用匹配的小节。

## 语言与依赖

- 服从项目声明的 JDK、Spring Boot、`javax`/`jakarta`、构建工具和依赖版本，不生成版本不支持的 API。
- 控制流语句使用花括号；命名、格式和 import 以项目 formatter/checkstyle 为准。
- 复用项目已引入的工具库；不要仅为字符串或集合判空新增 Hutool、Apache Commons 等依赖。
- 优先构造器注入以表达必需依赖并便于测试；若项目知识库或现有代码明确统一字段注入，则沿用项目方式。

## API 与模型

- 延续项目现有 URI、HTTP method、版本、响应包装和错误码约定。新项目默认使用资源语义清晰的 HTTP API，不把新增、修改、删除无条件合并为 `operateType` 接口。
- 单个简单查询参数可使用 query/path 参数；复杂筛选或可能持续扩展的查询使用请求对象。是否用 GET 或 POST 由项目约定、缓存语义、敏感性和请求大小共同决定。
- 请求模型使用 Bean Validation，并在入口用 `@Valid`/`@Validated` 触发；跨字段规则在合适层集中校验。
- 响应采用专用 VO/response 类型；同一结构可复用，语义或可见字段不同则拆分，避免用 Map 承载业务契约。
- OpenAPI/Swagger 注解跟随项目已有版本，不能混用 v2/v3。枚举字段应让可选值和含义可发现，优先使用枚举类型和 schema，而不是只写自由文本。
- 时间类型、时区和 JSON 格式服从项目统一策略。新项目优先 `java.time` 类型并明确业务时区；只有兼容既有契约时才固定 `java.util.Date` 或 `GMT+8`。

## 分层与持久化

- Controller 负责协议适配、校验和调用编排；核心业务与事务边界位于 Service/应用层；Mapper/Repository 负责数据访问。
- 是否创建 Service 接口由多实现、模块边界、测试替身和项目约定决定，不为每个类机械增加接口。
- MyBatis-Plus 简单单表查询优先使用类型安全的 lambda wrapper；复杂联表、报表或需精确优化的 SQL 放在项目约定的 XML/mapper 中。除非项目明确采用，不新增 SQL 注解风格。
- wrapper 的可选条件可使用条件参数链式构建；判空方式使用项目已有工具或 JDK 能力，不强制引入某个 utility 包。
- 实体映射、主键、逻辑删除和自动填充注解只按真实表结构添加。项目依赖命名映射时不强制为每个同名字段增加 `@TableField`。
- 分页复用项目已有 page request/result 抽象，并设置合理默认值和最大值；不要重复声明已有公共字段。
- 自定义 SQL 显式列名、参数化输入并检查索引使用；动态 SQL 使用框架安全构造，空集合和空条件行为必须明确。

## 事务、并发与异步

- 事务覆盖一个业务原子单元；需要受检异常回滚时明确 `rollbackFor`，并避免同类自调用绕过代理。
- 对重复请求、状态机迁移和共享资源更新选择唯一约束、乐观锁、悲观锁或分布式锁，并说明失败/重试语义。
- 非关键操作并不自动意味着应异步。只有延迟收益明确、调用方不依赖即时结果且失败可观测/补偿时才异步执行。
- 使用 Spring 管理的有界线程池或项目现有消息系统；不得调用未指定 executor 的 `CompletableFuture.runAsync`，也不得在 Service 内临时创建线程池。

## 配置与外部调用

- 使用 `@ConfigurationProperties` 承载成组配置并提供校验；动态刷新能力仅在项目使用 Nacos/Spring Cloud 且该配置确需运行时刷新时启用。
- Feign 客户端放在项目既有的 client/feign/integration 包；接口命名、fallback、超时、重试与鉴权沿用现有模式。重试仅用于满足幂等性的操作。
- 外部调用设置连接/读取超时，区分业务错误与传输错误；日志和异常不得包含 token、密钥或完整敏感报文。

## 最小验证清单

- 请求校验、鉴权、错误分支和空结果行为符合接口契约。
- 写操作事务、幂等和并发策略可解释；缓存一致性与 TTL 合理。
- SQL 无注入、无 `SELECT *`、无明显 N+1/无界查询，分页与索引符合访问模式。
- 异步任务有指定执行器、失败处理和上下文策略。
- DTO/VO、时间和枚举序列化与现有客户端兼容。
- 单元/集成测试覆盖主要成功路径及至少一个关键失败或边界路径。
