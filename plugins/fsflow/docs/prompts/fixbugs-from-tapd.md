# TAPD 缺陷修复

**适用**：缺陷来自 TAPD，需要拉取缺陷信息、定位根因、修复并验证回归。

## 可粘贴命令

```
/fsflow:fixbugs "TAPD 需求 <需求ID>，缺陷 <缺陷ID>：<现象描述>"
```

已知 storyId 时：

```
/fsflow:fixbugs BUG-042 "TAPD 需求 12345，缺陷 67890：订单列表页白屏"
```

## 最少要提供的信息

| 信息 | 为什么必需 |
|---|---|
| 需求 ID + 缺陷 ID | 用于拉取 TAPD 上下文，避免描述与系统记录不一致 |
| 现象 | 用户看到什么，不是你认为的原因 |
| 复现路径 | 在哪个页面、什么操作顺序、什么账号与数据 |
| 期望 | 正确行为是什么 |

环境、浏览器、报错日志有就附上，没有则说明「未获取」。

## 示例

```
/fsflow:fixbugs "TAPD 需求 12345，缺陷 67890：订单列表页白屏。
复现：运营账号登录后进入订单中心，筛选「退款中」，列表区域空白，控制台报 Cannot read property 'map' of undefined。
期望：正常展示退款中订单，无数据时显示空态。
环境：Chrome 120，测试环境，后端返回 data 为 null。"
```

## 注意事项

- 不要预设根因（比如直接写「后端少返回字段」）。根因由分析阶段确认，预设会跳过证据收集。
- 一次一个缺陷；同一根因的多个现象合并描述并在末尾列出全部缺陷 ID。
- 缺陷描述与 TAPD 记录不一致时以 TAPD 为准，代码里发现的新增问题单独记录，不混进本次修复。
