# 新功能开发

**适用**：有一个明确的功能需求，需要走「需求分析 → 任务规划 → 开发 → 审查 → 测试 → 交付」完整链路。

## 可粘贴命令

```
/fsflow:run "<需求描述>"
```

有设计稿时附链接，会自动启用设计契约门控：

```
/fsflow:run "<需求描述>" <Figma 链接>
```

## 需求描述要写全的四件事

1. **谁用、什么场景**：角色与触发入口。
2. **期望行为**：正常流程，加上为空、失败、无权限、超长文本时的表现。
3. **涉及范围**：前端页面 / 接口 / 数据表，能给路径就给路径。
4. **验收方式**：谁看、看什么、怎样算完成。

## 示例

```
/fsflow:run "运营在订单中心批量导出退款明细。
导出按钮放在列表页右上角，仅运营角色可见。
数据量大时分批导出并给进度提示，失败时保留已导出的部分并提示重试。
为空时提示「当前筛选条件无数据」。
涉及前端 src/views/order/ 与后端 export 接口，需要新加权限点。
验收：运营用一个 5000 条的筛选条件能导出完整 CSV。"
```

## 注意事项

- 不要写实现方案（用什么库、怎么分表）。方案由规划阶段产出，提前指定会让审查失去判断空间。
- 一次只描述一个功能；两件不相关的事分两次。
- `storyId` 可省略，流程会按需求生成；想固定编号时写在最前面：`/fsflow:run CS-001 "<需求>"`。
- 需求不确定时先直接发，流程会集中追问，比自行补全假设更省返工。
